# Visualization Pipeline v2.2.0

图表属于一级 evidence，不等到论文末期再临时美化。

## 1. 三角色职责

### CYQ / Paper Lead
决定：
- 为什么画；
- 图要证明什么；
- 哪种图最适合论文；
- 版面、标题和叙事是否清楚。

### FYQ / Technical Lead
负责：
- 正式数据；
- 可编辑绘图脚本；
- 输出格式；
- 从 Frozen Output 到 Figure Data 的 provenance。

### XXT / Mathematical Lead
负责：
- 指标含义；
- 数学逻辑；
- 是否存在误导性归一化、双轴或错误比较；
- 敏感性/机制图是否支持正文结论。

## 2. Figure Registry v2.1.1

使用 `templates/Figure_Registry模板.csv`。

字段：

- `figure_id`
- `question`
- `type`
- `purpose`
- `claim`
- `data_owner`
- `freeze_version`
- `source_file`
- `script`
- `time_scope`
- `window_rule`
- `selection_reason`
- `reviewer`
- `status`
- `layout_risk`

`type` 只允许：

- `result`：主结果；
- `mechanism`：解释机制；
- `diagnostic`：异常、不可行、残差、收敛、局部窗口；
- `robustness`：敏感性、稳健性、情景比较。

其中时间/窗口 provenance 必须可审计：

- `time_scope`：完整统计时域或图实际覆盖的时域；
- `window_rule`：窗口如何从全时域中选出，例如题目指定、固定末端窗口、误差最大窗口、调整最集中窗口；
- `selection_reason`：为什么该规则与要验证的 Claim 相关。

如果展示全时域，`window_rule=FULL_HORIZON`。如果图不涉及时间窗口，可写 `NOT_APPLICABLE`。不得为了图更明显、差异更大或版面更好看而事后挑选窗口。

状态：

```text
IDEA
→ DATA_SPECIFIED
→ DATA_LOCKED
→ DRAFT
→ FINAL
```

## 3. 建模阶段就规划图

在模型阶段提前问，按本问需要选择，不要求每问各画一张：

- 哪张图证明预测/分类/优化有效；
- 哪张图说明机制；
- 哪张图解释约束边界、适用范围或待诊断的异常；
- 哪张图证明参数选择或稳健性。

这样代码会主动导出所需原始数据。

## 4. Source of Truth

```text
Frozen Output
→ Figure Data
→ Figure Script
→ PDF/SVG/PNG
→ Paper
```

禁止：
- 从旧图抄数字；
- 从聊天记录抄数字；
- 从截图还原数据；
- 使用未冻结临时 CSV 作为 FINAL；
- 为了“图更好看”挑选没有业务依据的时间窗口。

需要局部窗口时，先写入 Figure Registry 的 `time_scope`、`window_rule` 和 `selection_reason`，再运行绘图脚本。窗口规则优先采用题目指定、预注册规则或与诊断目标直接相关的客观规则。

## 5. 正式图最低交付

重要正式图尽量同时保留：
- 可编辑绘图代码；
- PDF 或 SVG 矢量版；
- 300 dpi PNG；
- 对应原始 CSV；
- 单位、场景、统计范围和基准定义。

若比赛提交格式不需要全部版本，仓库内部仍应保留 provenance。

## 6. 版面 Gate

图表入文前检查：

- 正文首次引用与图位置合理；
- 不造成上一页大面积空白；
- 标题尽量不出现只剩 2–3 个字的跨行尾巴；
- 图例、字号按论文实际缩放尺寸仍可读；
- 单位、样本量、时间范围、场景在图注或正文交代；
- 双面板比较使用同一色标/坐标范围，除非正文明确说明差异；
- 多单位指标优先分面，不生硬塞到同一纵轴；
- 版面调整不得删除关键验证 evidence。

## 7. 结果解释

每张重要图至少对应一句清楚的比较目的和一个解释段：

比较目的 → 图 → 决定性数字/形状 → 机制/例外 → 对本问结论的作用。

不能只写“如图所示”。

## 8. 先讲求解，再展示效果与取舍

调度、优化和耦合迭代问题，先在模型建立之后展示本题算法流程或伪代码，再进入结果图。流程图讲模块关系，伪代码讲关键判断；若两者信息重复，保留足以讲清求解的一种。不要强迫简单统计问题画优化流程。

结果图先确定比较问题，再选图形；不是每类图都必须出现，也不是为了图多把表格重画一遍。

| 比较问题 | 可用图形 | 必须讲清 |
|---|---|---|
| 参数变化怎样影响成本、网络时延、等待时间 | 同横轴三联图或独立小图 | 各指标独立单位、同一参数顺序、基准与改善/退化方向 |
| 算法怎样迭代、为何停止 | 逐轮曲线和状态标记 | 接受/拒绝、停止原因；终止不自动等于收敛 |
| 任务移到哪里、何时执行 | 前后或差值热力图 | 同任务集、时域、容量分母；可比较的坐标与色标 |
| 参数配置有什么收益与代价 | 参数响应曲线、容量×功率图 | 每点来自对应配置的重求解，未运行点不补画成结果 |
| 约束边界怎样限制方案 | 边界曲线、缺口表 | 证据适用的模型、固定条件、求解范围与可能恢复可行的调整 |

成本、网络时延和等待时间不是同一指标，不合并成含义模糊的“时延”。等待时间需要按问题检查均值和尾部指标（如 P95）；不要仅凭均值掩盖少量任务的长等待。

参数比较应保持输入、目标、约束、初始方案和计算预算等非研究因素可比；确有差异时显式标注。场景变化与参数变化分开编码。多次随机运行时按需展示分布或误差范围。10%/20%/30% 只是本次 Q4 的候选实验例子，是否正式运行、各跑几轮以当前任务与配置为准，不能写进通用 Skill 成为固定要求。

图表展示真实改善和代价，不预设所有指标同时变好。成本为负、基准为零或接近零时，不套用通常的百分比降幅；优先报告绝对差额并解释购电支出、售电收入和净成本，不能把净成本下降自动解释为节能。归一化图需要说明定义并提供原值。

## 9. 边界证据不是笼统的“模型失败”

论文可用“约束可行域分析”“碳约束边界与配置建议”等具体标题，不默认给每问增加“失败诊断”章节。保留影响核心结论的边界与反例，不必把全部调试日志放正文。

先区分三件事：算法在预算内没找到解、固定排程的能源子问题不可行、联合模型已证明不可行。三者不能相互替代。局部或固定负荷下得到的最小碳排，只能在该范围内解释；未经全局证据不能写成系统理论极限。

有定量证据时，说明既定条件下的最低需求/最小可达值、原约束与缺口，并比较恢复可行的调整；仅有未知、超时或搜索失败时如实报告状态。模型缺陷应回传修复，不能仅改标题包装成现实边界。

## 10. 运行前把图表需求说清楚

在现有 Figure Registry 的 purpose/claim 中记录比较问题；详细字段、横纵轴、面板、baseline、参数、统计口径与证据槽位可写入配套图表卡或技术请求，不更改现有 CSV 接口。图后解释主要变化、机制、收益与代价，以及它支持的结论；篇幅紧张时只保留决定性的数字，不把整表重新念一遍。
