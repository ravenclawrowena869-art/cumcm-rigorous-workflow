# 逐问写作与算法呈现 Gate v2.2.0

本 Gate 适用于数学建模论文的每一个子问题。正文需要说明本题为何这样建模、如何求解、这种处理具体带来什么好处，以及结果凭什么可信。

## 零、本问中心链

每问写作优先围绕：

```text
本问要解决什么
→ 真正困难/约束是什么
→ 为什么采用当前处理
→ 这种处理对本题有什么具体好处
→ 实际如何求解
→ 哪些数字/图表/实验证明有效
→ 这个结论如何服务下一问或全文主线
```

如果一段方法介绍删掉题目变量名后仍能原样放进任何论文，说明它没有完成本问叙事任务。

## 一、大标题下短导语：避免重复“问题分析”

如果论文前文已经设置“问题分析”，各问题正式求解章节的大标题下不得再单独设置“本问目标与难点”“本问分析”等小节重复说明本问要解决什么、难点是什么。应改为**大标题下短导语**，随后直接进入耦合关系/建模依据或模型建立。

短导语用一段连贯文字承上启下。以下是论证功能，不是固定四句话，也不要求从表达库选句：

1. **任务概括**：简要概括本问需要完成的真实任务；
2. **核心难点**：指出决定建模路线的结构性难点、耦合关系或规模障碍；
3. **模型选择**：由该难点自然引出所选模型或求解方法，必要时只说明它在本问中承担的作用；
4. **应用依据**：最后说明该模型将“为哪个具体决策、比较或判断提供可靠依据”。

在模型选择与收束之间，可自然补一句后文将通过什么图表或对照展示哪些策略、参数或情景的差异。这样读者先知道结果要回答什么；不需要提前报告数字或宣告成功。Q1—Q3 同样适用，但须按各问的真实数据特征与方法改写，不强加耦合关系、改进算法或创新性。

完整概述可写成“本问任务 → 数据/约束带来的难点 → 方法及关键机制 → 图表或对照要展示什么 → 具体用途”。不要把它机械变成五个标题。措辞可选读[表达参考](07_表达参考.md)，也可以完全自行组织。

可记为：

```text
任务概括 → 核心难点 → 模型选择 → 应用依据
```

导语中不得展开变量、公式、算法步骤、参数表、实验结果或正式数字；尤其不得提前写入未冻结结果。即使结果已 Frozen，也应把正式数字和结果解释放到“结果及证据”部分，而不是塞进导语。

收束句必须有具体对象，例如“为不同场景下的调度策略比较提供可靠依据”“为后续资源配置决策提供可靠依据”。禁止只写“提供重要支撑”“具有科学有效性”等无具体对象的评价。

### 示例：耦合优化问题

> 问题四要求统筹六个区域的 AI 任务调度与能源管理，在满足任务时限、网络时延、GPU 与功率容量、储能运行及电网交易等约束的基础上，协调运行成本、碳排放与服务质量。然而，任务排程决定数据中心负荷的时空分布，能源调度形成的边际代价又会反过来影响任务迁移，二者相互耦合，直接建立统一优化模型将面临较大的求解规模。因此，本文采用基于能源边际信号反馈的交替优化方法，将任务调度与能源优化分解求解，并通过可行性校验、联合验收与回滚机制控制迭代过程，为不同运行场景下算力资源与能源资源的协同配置提供可靠依据。

该示例只展示“任务—难点—方法—用途”的因果结构，不是固定模板。不同问题必须按真实任务替换任务概括、核心难点、模型选择和应用依据；不存在耦合关系时，不得机械写“相互耦合”。

## 二、逐问正文推荐顺序

默认采用：

```text
大标题下短导语
→ 耦合关系/建模依据
→ 模型建立
→ 求解算法与伪代码
→ 结果及证据
→ 本问小结
```

其中“耦合关系/建模依据”应按本题结构理解：存在耦合时说明变量或子系统如何相互作用；不存在耦合时说明数据结构、约束结构、统计规律或物理机制为何支持当前模型。

篇幅紧张时，可以删除单独的“本问小结”，但**不能删掉结果解释**，也不能只保留图表或数字而不说明其机制、意义与题目回答。

## 三、算法或模型必须先由难点引出，再给公式

引出段必须回答：

- 题目中的哪种数据结构、约束或规模特征决定了模型选择；
- 当前方法相对至少一个合理备选的优势是什么；
- 该优势怎样服务本题目标，例如提高可行率、降低搜索规模、保护 QoS、减少风险或改善解释性；
- 该优势由什么比较、复杂度分析或既有证据支持；
- 方法的代价或适用边界是什么。

禁止先宣布“本文采用某高级算法”，再反向拼接理由。方法必须由前述核心难点自然推出。

禁止教材式介绍，例如“某算法具有精度高、速度快、适用范围广等优点”。没有本题证据的通用优点不通过。

## 四、每问必须给出题目特定的求解过程

每问至少包含以下一种：

- 非平凡算法的伪代码；
- 与实际变量、约束对应的算法流程图；
- 对闭式计算或简单统计模型的逐步计算流程。

伪代码或流程必须与正文公式和正式代码一致，并包含：

- 实际输入文件或输入变量；
- 输出对象；
- 初始化；
- 排序、循环、候选生成或求解步骤；
- 关键 hard constraints；
- 接受条件（如适用）；
- 停止条件；
- 无可行解、数值失败或边界样本的处理；
- 最终指标独立复算与输出。

以下形式不通过：

```text
输入数据 → 数据预处理 → 建立模型 → 调用算法求解 → 输出结果
```

合格流程应让读者看出处理什么对象、按什么准则选择、为什么这一步必要、何时拒绝候选、何时停止。

## 五、结果段的证据顺序

推荐顺序：

1. 一句说明比较目的或评价口径；
2. 图表；
3. 解释决定性数字、相对 baseline、机制和例外；
4. 说明这些结果具体证明了方法哪一项好处；
5. 说明本问结论如何回答题目或传递到下一问。

表格应置于主要解释段之前。不得先在正文逐项报完数字，再放重复表格。

每个图表必须同时满足：

- 有连续编号和完整图题/表题；
- 正文明确引用；
- 引用编号实际存在；
- 单位、场景、版本和正文一致；
- 数据来自 Frozen Output；
- 图表后有结论，不只写“结果如图所示”。

## 六、模型优点、稳健性和局限就地呈现

- 模型选择处说明优势及证据，不把全部优点拖到最后一章；
- 声称稳定、鲁棒、不敏感、优于之前，必须有对应实验；
- 数值稳定性、参数敏感性、决策稳健性和统计不确定性分开表述；
- 每个局限对应具体失效条件或缺失机制，并给出可实施的改进方向；
- hard constraint 满足只能证明可行，不能单独证明算法优越。

## 七、反例与语言 Gate

以下写法不通过：

- 在正式求解章节下再次设置“本问目标与难点”，重复前文问题分析；
- 导语过长，提前塞入大量符号、公式、参数、实验结果或正式数字；
- 先说“本文采用某高级算法”，却没有从题目难点自然推导方法；
- 使用“显著提升、科学有效、提供重要支撑”等没有具体对象或证据的空泛结尾；
- “为避免……这里需要说明的是……”等写作过程或防错提醒；
- “显然、天然地、充分地、很好地、进一步地”等无信息增量修饰；
- 反复复述题意、公式和表格；
- 没有数据支撑的“效果显著、模型优越、具有较强推广性”；
- 只讲算法常识、不解释本题选择的段落；
- 只按模型名称堆叠句子、没有主谓宾和因果关系的模板腔。

正文直接陈述定义、依据、步骤、数字和结论。技术 Handoff 进入论文前，应恢复成自然的人类论证顺序，不照抄 Agent 日志。

## 八、排版与交叉引用 Gate

- 表、图、公式编号连续，正文不得引用不存在或无题名对象；
- 文献引用格式与官方模板一致，角标/编号不得错位；
- 标题不得只剩少量文字跨行，必要时调整字号、宽度或措辞；
- 最终 PDF 逐页检查大块空白、孤行、图表漂移、遮挡、字号过小和分页不自然；
- 版面调整不得通过删除关键验证 evidence 完成。

## 九、AI 阻断规则

AI 在写作或审稿时，如发现以下任一情况，必须列出缺口并停止生成“可直接定稿”的表述：

- 缺少 Paper Handoff 或正式结果来源；
- 需要伪代码但没有真实求解步骤；
- 模型选择没有备选或证据；
- 稳健性结论没有实验；
- 图表/表格编号与正文不一致；
- 结论超出模型实际优化目标或数据支持范围。

允许输出带明确占位符的草稿，但不得用通用语言掩盖 evidence 缺失。

## 十、逐问通过清单

- [ ] 若前文已有“问题分析”，正式求解章节没有再设置“本问目标与难点”等重复小节；
- [ ] 大标题下短导语按“任务概括 → 核心难点 → 模型选择 → 应用依据”完成承上启下；
- [ ] 核心难点能够自然引出当前方法，而不是先报算法名称再补理由；
- [ ] 导语没有变量、公式、算法步骤、正式数字或未冻结结果；
- [ ] 收束句明确说明模型为哪个具体决策、比较或判断提供依据；
- [ ] 正文顺序覆盖“建模依据 → 模型建立 → 求解算法与伪代码 → 结果及证据”；
- [ ] 如果删除本问小结，结果解释仍完整保留；
- [ ] 方法引出与本题数据、变量或约束直接相关；
- [ ] 说明了选择当前方法而非备选的依据；
- [ ] 有题目特定的伪代码、流程图或计算流程；
- [ ] 求解步骤与公式、代码、接受/停止条件一致；
- [ ] 主要结论有 baseline、数字和 Frozen source；
- [ ] 优点在对应模型处有证据地呈现；
- [ ] 稳定性/敏感性/鲁棒性结论均有实验；
- [ ] 结果明确说明如何服务下一问或全文结论；
- [ ] 图表编号、题名、引用完整；
- [ ] 不存在通用算法介绍、元叙述和空泛评价；
- [ ] PDF 逐页版面检查通过。
