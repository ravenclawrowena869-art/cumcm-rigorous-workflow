# 参数选择协议 v1.0

本协议用于所有会 materially 影响可行性、目标值、模型结论、收敛行为、服务质量或论文 Claim 的参数，包括但不限于：权重、惩罚系数、阈值、迭代步长、每轮调整比例、置信水平、风险参数、Top-K、平滑系数、容量/预算设定以及人为规则常数。

核心原则：**参数不能只被“定下来”，必须说明它为什么存在、为什么在这个范围内研究、为什么最终采用这个值或这套自适应规则。**

---

## 一、先判断参数的数学身份

在扫参数之前，先回答：

1. 该参数代表现实/业务量、统计量、模型结构参数，还是纯算法控制参数？
2. 它是否由题面、官方标准、物理边界或数据直接给定？
3. 它是否真的需要固定成常数？
4. 是否可以通过解析推导、交叉验证、优化、信赖域/线搜索、自适应更新或约束重写消除手工定值？

如果参数本质上是迭代步长、更新半径、每轮调整比例、阻尼系数等算法控制量，不得默认“固定常数”是唯一形式；应至少讨论固定值与自适应规则哪一种更符合问题结构。

---

## 二、参数依据的优先级

确定搜索范围前，按以下优先级寻找 evidence：

1. **题面 / 官方规则 / 明确业务约束**；
2. **物理、数学或统计理论边界**；
3. **定义和尺度真正可比的领域文献 / 标准 / 工业实践**；
4. **本题数据的 EDA、历史分布、pilot experiment 或小规模 exact anchor**；
5. **计算预算与工程约束**。

文献优先寻找，但不是机械硬要求。若没有与本参数“定义、尺度、作用机制”可比的文献，不得为了有引用而搬用相似数字。此时应明确写“缺少直接可比先验”，改由理论边界 + 数据 pilot + 敏感性/稳定性验证确定范围。

**禁止数字移植：** 另一篇论文中的“20%可转移负荷比例”不能直接证明本题“每轮最多调整20%任务”合理，除非二者参数定义和作用机制一致。文献可以缩小先验搜索区间，不能单独证明最终参数最优。

---

## 三、先定合理范围，再设计实验点

必须先记录：

- 参数定义；
- 合理下界与上界；
- 下/上界的来源；
- 为什么不研究范围外的值；
- 当前是否已有经验基准值。

实验点由“范围 + 目的”决定，而不是先拍脑袋列 10%、20%、30%。

### 仅做局部敏感性

若已有外部或理论支持的基准值，可在其两侧设置扰动点，用于回答“结果对该参数是否敏感”。这种实验**不能**证明基准值是全范围最优。

### 需要真正选择参数

优先采用：

`先验范围 → 粗粒度 screening → 定位拐点/失效区间 → 局部加密 → 邻域复核`

粗扫的作用只是探索响应曲线和缩小候选区间，不是参数最优性证明。

若单次求解很便宜，可直接做较密网格；若参数维度较高，可使用 DOE、Bayesian Optimization、随机搜索、进化算法等，但仍需保留可解释的搜索空间来源与最终选择准则。

---

## 四、选择准则必须事先定义

不得看到结果后再挑一个最顺眼的参数。

在运行前明确：

- hard constraints / SLA / 可行性 Gate；
- 主目标；
- 次要指标；
- 可接受服务质量边界；
- 是否使用 Pareto、ε-constraint、膝点或 lexicographic 规则；
- 若多个参数性能近似，优先简单、稳定、计算代价低还是风险低。

多目标问题不得仅凭“成本最低”选择参数。如果参数降低成本却显著恶化等待时间、时延、峰值、碳排或其他题目要求指标，应使用 Pareto / 膝点 / 主目标—约束结构解释取舍。

---

## 五、算法控制参数优先检查“自适应”而非只扫固定值

对步长、更新半径、每轮调整比例、阻尼、平滑系数等参数，至少问一次：

> 该参数是否应随迭代状态、模型预测可信度、可行裕量或 QoS 反馈动态变化？

如果存在合理自适应机制，应比较：

- 一个或多个固定基线；
- 自适应方案。

例如交替优化中的任务调整比例可解释为离散排程空间的更新半径；若实际改善低于预测、QoS恶化或子问题接近不可行，可缩小更新半径；若预测改善兑现且 QoS 稳定，可适度扩大。

不能因为“固定值实现简单”就跳过这一结构性判断。

---

## 六、参数实验必须重新求解并保留完整指标

改变参数后必须重新运行对应模型/下游流程，不得只基于已求得最优解做事后相关图。

每个参数点至少记录：

- 参数值 / 参数组合；
- solver / model / upstream 版本；
- 可行性与停止原因；
- 主目标；
- 题目要求的关键指标；
- 服务质量指标；
- 收敛轮数 / runtime（适用时）；
- 随机种子 / 重复编号（适用时）。

参数影响下游决策时，应做 full replay，而不是只验证 surrogate score。

---

## 七、最终参数必须做邻域与跨场景复核

选出候选参数后，至少检查：

- 邻近取值是否会推翻结论；
- 不同随机种子 / 初始点是否稳定；
- 关键代表场景下是否仍可行；
- 是否存在明显 cliff / threshold effect；
- 若只在单一场景最优，是否应改为场景相关或自适应参数。

若不同场景的合理参数明显不同，不得强行宣称一个全局固定值“最优”。应考虑：

- 分场景参数；
- 自适应规则；
- 或在论文中明确参数的适用范围。

---

## 八、论文中的推荐表达

参数选择至少形成以下证据链：

> **参数语义 → 外部/理论依据 → 合理范围 → 实验设计 → 选择准则 → 最终值/自适应规则 → 邻域与场景稳定性。**

可用写法：

> 根据题面约束、相关研究与本题 pilot 结果，先将参数的候选范围限制为……。粗粒度实验表明……区间出现明显收益饱和/可行性变化，因此在该区间进一步加密比较。综合主目标、服务质量和收敛速度，最终采用……。在相邻取值及代表性场景下，核心结论未发生结构性改变。

若文献只提供间接先验，应如实写“用于确定初始搜索区间”，不能写成“文献证明该值最优”。

---

## 九、Parameter Evidence Gate

关键参数只有满足以下条件才允许写成正式值：

- [ ] 参数的现实/数学/算法含义明确；
- [ ] 已判断它是否必须固定；
- [ ] 搜索范围有题面、理论、可比文献、数据或 pilot 依据；
- [ ] 不存在把不同定义参数的文献数值直接移植的问题；
- [ ] 实验点的选择与实验目的匹配；
- [ ] 改参数后进行了重新求解 / full replay；
- [ ] 最终选择准则在看结果前已定义或至少可明确复现；
- [ ] 多目标参数选择同时考虑服务质量/风险，而非只看单一目标；
- [ ] 最终值经过邻域或跨场景复核；
- [ ] 若参数本质是步长/更新半径，已检查固定 vs 自适应的合理性；
- [ ] 论文能够用一段话完整回答“为什么是这个参数”。

任一会 materially 改变核心 Claim 的参数若不满足上述证据链，应标记 `FAIL / ADD EXPERIMENT`，而不是以“经验取值”直接 Freeze。
