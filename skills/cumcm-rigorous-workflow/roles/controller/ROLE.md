# 总控角色入口

用于 `ACTIVE_ROLE=FYQ_TECHNICAL_ORCHESTRATOR`。这是同一 Skill 内的导航，不是另一个 Skill 或新的权限来源。

## 起点

完成[总入口](../../../../SKILL.md)的 Shared Core 与角色绑定步骤后，读取[现有 FYQ Profile](../../profiles/FYQ_TECHNICAL_ORCHESTRATOR.md)。下表按本次任务选读，不必全部加载。

| 本次任务 | 阅读材料 | 交付重点 |
|---|---|---|
| 拆分任务、安排依赖 | [共同维护与四类交接](../../../../06_协作与交接/06_三GPT协作与Skill共同维护.md)、[任务单模板](../../../../templates/任务单模板.md) | Owner、输入输出、允许修改、验收与下一接收人 |
| 组织实验与验收 | [模型证据 Gate](../../../../04_验收冻结/05_模型证据充分性Gate.md)；涉及参数再读[参数协议](../../../../03_建模与代码/05_参数选择协议.md) | 基线与实验范围、当前版本验证、未闭合证据 |
| 给论文线交付 | [两级论文交接](../../../../06_协作与交接/05_Paper_Handoff规范.md) | `TECH_DIRECTION_STABLE` 后交 Brief，冻结后交自描述的正式事实与来源 |
| 正式出图 | [图表工作流](../../../../05_论文与图表/02_图表工作流.md) | 数据、脚本、版本；由 CYQ 判断叙事，XXT 判断指标 |
| 最终提交 | [提交 Gate](../../../../08_提交终检/01_FINAL_SUBMISSION_GATE.md) | 按实际提交要求验收，不以技术跑通替代提交检查 |

修改 Skill 继续执行总入口的 Repository Write Gate。数学否决、冻结前置与交付权限以 Profile / Shared Core 为准，此处不另订一套。技术卡住时按任务范围安排备用工作，不把技术总控转给论文手。
