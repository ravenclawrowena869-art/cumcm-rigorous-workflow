# 项目状态机与角色责任

每个问题或模块统一使用：

```text
IDEA
 ↓
BASELINE
 ↓
MAINLINE
 ↓
VALIDATING
 ↓
FROZEN
 ↓
PAPER_LOCKED
```

可选：
- BLOCKED
- FAILED_VALIDATION
- REOPENED_BY_P0

## 状态负责人

### MAINLINE
Owner 对模块进度负责。

### VALIDATING
- FYQ：Technical Check
- XXT：Mathematical Check

### FROZEN
FYQ 维护技术 Source of Truth；
XXT确认数学口径不再变化。

### PAPER_LOCKED
CYQ完成 Paper Check 后进入。

---

# 三重验收

## Technical PASS — FYQ
- 输入
- 代码
- tests
- interface
- version
- clean replay
- manifest
- paper metrics source

## Mathematical PASS — XXT
- 数学定义
- 目标
- 约束
- 假设
- 指标
- 边界
- 数值合理性
- 求解逻辑

## Paper PASS — CYQ
- 能否讲清楚
- 结果是否支持结论
- 图表是否有效
- 与全文是否一致
- 是否过度复杂
- 是否存在明显 AI 味

三者通过后才能 `PAPER_LOCKED`。

---

# 冻结后允许修改

允许：
- 不影响模型结果的路径兼容
- README
- 注释
- 图表样式
- 论文表述
- 打包问题

禁止：
- 目标函数
- 关键约束
- 正式指标口径
- 核心参数
- 手工修改 frozen output

如发现 P0：
1. 宣布 `REOPENED_BY_P0`
2. 新版本
3. 重跑依赖
4. 更新 paper metrics
5. 重画相关图
6. 重新 Paper Check
