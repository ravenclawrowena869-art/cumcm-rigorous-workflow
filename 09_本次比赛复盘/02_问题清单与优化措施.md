# 本次比赛问题清单与 v2.1 对应改造

| 本次出现的问题 | 根因 | v2.0 机制 |
|---|---|---|
| Leader 承担过多技术总控 | Leader 与 Model Integrator 合并 | Paper / Technical / Mathematical 三角色拆分 |
| 一人必须等另一人结果 | 结果依赖被误当成开发依赖 | Interface First + Mock Data |
| FYQ/XXT 曾因工具或任务状态调整角色 | 容灾发生在人员层 | 工具→设备→人员三级容灾 |
| 论文启动太晚 | 把论文当成后期阶段 | 第一次路线评审后立即启动 Paper Pipeline |
| 图表返工多 | 图表被当成最后美化 | Figure Registry + Visualization Pipeline |
| 版本迭代过密 | 小修补也升级核心版本 | 状态机 + Freeze + P0 reopen |
| Q4 集成阻塞 | 接口较晚固定 | 8–10h 前尽量锁 interface schema |
| 指标口径风险 | Paper metrics 未统一 | Paper Handoff + number registry |
| 论文超页后才集中压缩 | 无页数预算 | 前期章节预算 + 持续页数预审 |
| AI 修改容易扩大范围 | Prompt 缺 non-goal | 平台无关 Skill + allow/forbid + validation |
| 团队出现纯等待 | 无备用任务机制 | Blocked Rule + Secondary Queue |
| 模型完成后仍大量工程修补 | 把“跑出来”视为完成 | Technical / Mathematical / Paper 三重验收 |

| 每问大标题后缺少方法与结果概述 | 把章节标题当作结构，不把它当成评委的快速阅读入口 | 逐问写作 Gate 强制输入—困难—方法—评价—结果概述 |
| 求解过程只有公式和文字，没有伪代码 | Paper Handoff 未交付真实算法步骤 | 每问必须有题目特定伪代码/流程，包含约束、停止和失败分支 |
| 算法介绍偏通用，未说明为何适合本题 | 先写算法常识，后补题目变量 | 模型引出必须绑定数据结构、约束、规模、备选比较和适用边界 |
| 模型优点只在末章笼统总结 | 模型选择与验证证据未就地进入正文 | 优点在对应模型处以“设计—证据—边界”呈现 |
| 缺少稳健性、参数敏感性与真值锚点 | 将“结果可行”误当成“方法可信” | 新增模型证据充分性 Gate |
| 启发式调度未检查输入顺序 | 排序并列规则与输入行序未进入验收 | 强制重排、多种子、多起点与结果分布 |
| 多目标只比较预设策略 | 缺少极端点、精确解或下界 | 代表性子问题 MILP/DP/枚举锚点或可核验下界 |
| 预测区间未量化决策保护效果 | 不确定性停留在预测展示 | 检查覆盖率、区间宽度及下游容量/风险保护 |
| 分区独立等结构假设无对照 | 假设只写在“模型假设”中 | 对照仿真、理想上界或容量受限情景 |
| 经验阈值无选择依据 | 参数来自调试习惯 | 参数扫描后重新求解，报告拐点与边际收益 |
| 迭代终止只重视主目标 | 服务质量只做事后统计 | 每轮同时记录主目标、QoS、可行性和停止原因 |
| 不可行性解释停留在“约束过严” | 未计算最小可达边界 | 最小边界、最小松弛、IIS/绑定约束与物理机制解释 |
| 表格无题名或正文引用不存在 | 图表注册与排版终检脱节 | Figure/Table Registry + 交叉引用 Gate |
| 表格位于解释之后、图文重复 | 结果段没有统一证据顺序 | 比较口径→图表→解释→结论/下游接口 |
| 参考文献角标与版面不规范 | 最终 PDF 只查页数和内容 | 引用格式、标题跨行、大块空白与逐页渲染检查 |
| 部分段落有 AI 味 | AI 用通用过渡句填补证据缺口 | 缺证据时阻断定稿，删除元叙述和空泛修饰 |
