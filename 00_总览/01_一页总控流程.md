# 五级主 Gate

## G0 — Problem Contract
必须确认：
- 官方要求；
- 数据字典；
- 时域 / 单位；
- 各问真实依赖；
- 提交规则；
- AI 使用规则；
- 第一版模型路线；
- 跨问接口草案。

## G1 — Runnable Mainline
每问至少：
- 一个 baseline；
- 一条可运行主线；
- 一个稳定输出 schema；
- 基本 hard constraint 检查。

## G2 — Mathematical & Technical Validation
必须：
- hard violation = 0；
- 数学审核通过；
- 技术审核通过；
- 指标口径固定；
- 接口稳定；
- 模型证据充分性 Gate 完成；
- Triggered Gate List 已生成；
- 被触发 Gate 已执行或明确 limitation；
- 独立 Red Team 已完成。

### G2 的条件触发 Gate

只有满足触发条件时才执行，不要求所有题机械跑全套：

- CG1：关键假设挑战；
- CG2：路径/顺序依赖；
- CG3：启发式质量锚点；
- CG4：可行余量；
- CG5：反馈安全；
- CG6：派生信号语义验证；
- CG7：收敛可信度；
- CG8：边界与局部窗口；
- CG9：对照公平；
- CG10：数量级与物理合理性。

详细标准见 `04_验收冻结/06_条件触发Gate与证据协议.md`。

## G3 — Freeze
必须：
- clean replay；
- manifest；
- source of truth；
- paper metrics；
- figure data；
- 三重验收完成；
- Gate Evidence 完整；
- Red Team 阻断项关闭；
- waiver 必须伴随 Claim 缩小。

## G4 — Submission
必须：
- 摘要/正文数字一致；
- 图表来源一致；
- 页数与格式合规；
- AI 说明合规；
- 所有被触发 Gate 已 PASS 或有明确 limitation；
- PDF/附件最终人工检查。

# Gate 的证据原则

Gate 不接受“应该没问题”。

每个关键 Gate 至少记录：

- 为什么触发；
- Owner；
- 非 Owner Reviewer；
- 判定标准；
- Evidence 文件；
- 状态；
- limitation / waiver。

`PASS` 不是一句话，而是一组可复查证据。

# 两条禁令

## No Pure Waiting
任何成员的主任务被依赖阻塞超过约 15–30 分钟，应切换 Secondary Queue。

## No Role Swap for Tool Failure
Codex / Claude Code / 网络 / 单一工具故障，优先切换工具或设备。
不得因为 coding agent 故障就重排 FYQ / XXT 的长期角色。
