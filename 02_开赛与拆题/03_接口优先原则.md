# Interface First + Mock Data

多问耦合题不得等待上游 FINAL 才开发下游。

## 在正式结果出来以前先冻结接口

至少固定：

- 文件名
- schema
- 主键
- time index
- region index
- unit
- precision
- missing semantics
- feasibility flag
- scenario_id
- iteration_id
- version

---

# Mock 数据

如果 Q2 依赖 Q1：

```text
Q1 正式结果尚未完成
        ↓
先提供 mock_q1_output.csv
        ↓
Q2 完成 reader / model / validator / output
        ↓
Q1 FROZEN
        ↓
只替换正式输入重新运行
```

联合模型也一样：

```text
mock_ai_it_load.csv
mock_energy_signal.csv
```

任务层和能源层从第一天就可以同时开发。

# 接口变更规则

接口 schema 一旦由 Technical Lead 标记 `LOCKED`：

未经 Technical Lead 同意不得改字段。

如确需变更：
1. 新 schema version
2. 更新 mock
3. 更新 producer tests
4. 更新 consumer tests
5. 记录 migration note

---

# 目的

我们要消除的是“开发依赖”，而不是数学上的真实依赖。

正式结果仍然可以有先后关系，
但代码、验证器、图表数据流水线不应该因为上游没跑完而闲置。
