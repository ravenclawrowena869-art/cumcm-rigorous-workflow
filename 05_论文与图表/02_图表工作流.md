# Visualization Pipeline v2.1

图表属于一级 evidence，不等到论文末期再临时美化。

## 1. 三角色职责

### CYQ / Paper Lead
决定：
- 为什么画；
- 图要证明什么；
- 哪种图最适合论文；
- 版面、标题和叙事是否清楚。

### FYQ / Technical Lead
负责：
- 正式数据；
- 可编辑绘图脚本；
- 输出格式；
- 从 Frozen Output 到 Figure Data 的 provenance。

### XXT / Mathematical Lead
负责：
- 指标含义；
- 数学逻辑；
- 是否存在误导性归一化、双轴或错误比较；
- 敏感性/机制图是否支持正文结论。

## 2. Figure Registry v2

使用 `templates/Figure_Registry模板.csv`。

字段：

- `figure_id`
- `question`
- `type`
- `purpose`
- `claim`
- `data_owner`
- `freeze_version`
- `source_file`
- `script`
- `reviewer`
- `status`
- `layout_risk`

`type` 只允许：

- `result`：主结果；
- `mechanism`：解释机制；
- `diagnostic`：异常、不可行、残差、收敛、局部窗口；
- `robustness`：敏感性、稳健性、情景比较。

状态：

```text
IDEA
→ DATA_SPECIFIED
→ DATA_LOCKED
→ DRAFT
→ FINAL
```

## 3. 建模阶段就规划图

在模型阶段提前问：

- 哪张图证明预测/分类/优化有效；
- 哪张图说明机制；
- 哪张图暴露异常和失败边界；
- 哪张图证明参数选择或稳健性。

这样代码会主动导出所需原始数据。

## 4. Source of Truth

```text
Frozen Output
→ Figure Data
→ Figure Script
→ PDF/SVG/PNG
→ Paper
```

禁止：
- 从旧图抄数字；
- 从聊天记录抄数字；
- 从截图还原数据；
- 使用未冻结临时 CSV 作为 FINAL；
- 为了“图更好看”挑选没有业务依据的时间窗口。

需要局部窗口时，先给选择规则，例如调整最集中、误差最大、终端阶段或题目指定窗口。

## 5. 正式图最低交付

重要正式图尽量同时保留：
- 可编辑绘图代码；
- PDF 或 SVG 矢量版；
- 300 dpi PNG；
- 对应原始 CSV；
- 单位、场景、统计范围和基准定义。

若比赛提交格式不需要全部版本，仓库内部仍应保留 provenance。

## 6. 版面 Gate

图表入文前检查：

- 正文首次引用与图位置合理；
- 不造成上一页大面积空白；
- 标题尽量不出现只剩 2–3 个字的跨行尾巴；
- 图例、字号按论文实际缩放尺寸仍可读；
- 单位、样本量、时间范围、场景在图注或正文交代；
- 双面板比较使用同一色标/坐标范围，除非正文明确说明差异；
- 多单位指标优先分面，不生硬塞到同一纵轴；
- 版面调整不得删除关键验证 evidence。

## 7. 结果解释

每张重要图至少对应一句清楚的比较目的和一个解释段：

比较目的 → 图 → 决定性数字/形状 → 机制/例外 → 对本问结论的作用。

不能只写“如图所示”。
