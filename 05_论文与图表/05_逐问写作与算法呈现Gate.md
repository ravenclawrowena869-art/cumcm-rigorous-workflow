# 逐问写作与算法呈现 Gate

本 Gate 适用于数学建模论文的每一个子问题。目标是让正文说明“本题为何这样建模、如何求解、结果凭什么可信”，而不是把通用算法介绍拼接到论文中。

## 一、每问开头必须有问题概述

每个问题的大标题后、首个二级标题前，写一段 3–5 句的本问概述，依次交代：

1. 本问的输入、固定条件和目标输出；
2. 数据或决策结构中的关键困难；
3. 采用的模型与求解路线；
4. 主要评价方法；
5. 已冻结时给出最关键结果，未冻结时保留显式占位符。

概述不是摘要原句的复制，也不能只写“本问建立模型并进行求解”。

## 二、算法或模型必须先引出，再给公式

引出段必须回答：

- 题目中的哪种数据结构、约束或规模特征决定了模型选择；
- 当前方法相对至少一个合理备选的优势是什么；
- 该优势由什么比较、复杂度分析或既有证据支持；
- 方法的代价或适用边界是什么。

禁止写成教材式介绍，例如“某算法具有精度高、速度快、适用范围广等优点”。若删去题目变量名后仍可原样用于任意论文，则视为通用性语言，不通过。

## 三、每问必须给出题目特定的求解过程

每问至少包含以下一种：

- 非平凡算法的伪代码；
- 与实际变量、约束对应的算法流程图；
- 对闭式计算或简单统计模型的逐步计算流程。

伪代码或流程必须与正文公式和正式代码一致，并包含：

- 实际输入文件或输入变量；
- 输出对象；
- 初始化；
- 排序、循环、候选生成或求解步骤；
- 关键硬约束检查；
- 停止条件；
- 无可行解、数值失败或边界样本的处理；
- 最终指标复算与输出。

以下形式不通过：

```text
输入数据 → 数据预处理 → 建立模型 → 调用算法求解 → 输出结果
```

合格流程必须能让读者看出“处理什么对象、按什么准则选择、何时拒绝候选、何时停止”。

## 四、结果段的证据顺序

推荐顺序：

1. 一句说明比较目的或评价口径；
2. 图表；
3. 解释决定性数字、相对基线、机制和例外；
4. 说明本问结论如何回答题目或传递到下一问。

表格应置于主要解释段之前。不得先在正文中逐项报完数字，再放一张重复表格。

每个图表必须同时满足：

- 有连续编号和完整图题/表题；
- 正文明确引用；
- 引用编号实际存在；
- 单位、场景、版本和正文一致；
- 数据来自冻结结果；
- 图表后有结论，不只写“结果如图所示”。

## 五、模型优点、稳健性和局限必须就地呈现

- 模型选择处说明优势及证据，不把全部优点拖到最后一章；
- 声称“稳定、鲁棒、不敏感、优于”之前，必须有对应实验；
- 稳定性、敏感性和鲁棒性分开表述；
- 每个局限对应具体失效条件或缺失机制，并给出可实施的改进方向；
- 不把硬约束满足写成算法优越性的充分证明。

## 六、语言 Gate

删除或改写：

- “为避免……这里需要说明的是……”等写作过程或防错提醒；
- “显然、天然地、充分地、很好地、进一步地”等无信息增量修饰；
- 反复复述题意、公式和表格；
- 没有数据支撑的“效果显著、模型优越、具有较强推广性”；
- 只讲算法常识、不解释本题选择的段落。

正文应直接陈述定义、依据、步骤、数字和结论。

## 七、排版与交叉引用 Gate

- 表、图、公式编号连续，正文不得引用不存在或无题名的对象；
- 文献引用格式与官方模板一致，角标/编号不得错位；
- 标题不得只剩少量文字跨行，必要时调整字号、宽度或措辞；
- 最终 PDF 逐页检查大块空白、孤行、图表漂移、遮挡、字号过小和分页不自然；
- 版面调整不得通过删除关键验证证据来完成。

## 八、AI 的阻断规则

AI 在写作或审稿时，如发现以下任一情况，必须列出缺口并停止生成“可直接定稿”的表述：

- 缺少 Paper Handoff 或正式结果来源；
- 需要伪代码但没有真实求解步骤；
- 模型选择没有备选或证据；
- 稳健性结论没有实验；
- 图表/表格编号与正文不一致；
- 结论超出模型实际优化目标或数据支持范围。

允许输出带明确占位符的草稿，但不得用通用语言掩盖证据缺失。

## 九、逐问通过清单

- [ ] 大标题后有本问概述；
- [ ] 方法引出与本题数据、变量或约束直接相关；
- [ ] 说明了选择当前方法而非备选的依据；
- [ ] 有题目特定的伪代码、流程图或计算流程；
- [ ] 求解步骤与公式、代码和停止条件一致；
- [ ] 主要结论有基线、数字和冻结来源；
- [ ] 优点在对应模型处有证据地呈现；
- [ ] 稳定性/敏感性/鲁棒性结论均有实验；
- [ ] 图表先于主要解释段，且编号、题名、引用完整；
- [ ] 不存在通用算法介绍、元叙述和空泛评价；
- [ ] PDF 逐页版面检查通过。
