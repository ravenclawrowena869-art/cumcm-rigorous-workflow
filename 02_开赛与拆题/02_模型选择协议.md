# 模型选择协议

## 每问最多保留

- 1 个 baseline；
- 1 个主模型；
- 1 个必要时的备选。

不要在比赛中同时维护 5 个“可能更高级”的模型。

## 模型选择优先级

1. 题意贴合；
2. 可解释；
3. 可复现；
4. 在时间内可求解；
5. 有可比较 baseline；
6. 能产生论文需要的结果；
7. 最后才是算法“高级程度”。

## MODEL-TOURNAMENT-001：候选路线小样锦标赛

当某一问存在两条以上合理路线、当前 baseline 暴露出明确结构缺口，或团队对主模型选择存在实质分歧时，推荐在正式大规模求解前做一次**小样锦标赛**，用低成本实验淘汰不合格路线。

### 参赛前资格门

候选若出现以下任一情况，不进入锦标赛：

- 违反题面固定条件或 hard constraints；
- 依赖比赛时不可获得的关键数据；
- 存在明显 target leakage / future leakage；
- 无法在赛时预算内稳定实现；
- 不能产生题目要求的输出；
- 关键结果没有可设计的验证方案。

### 原型比较规则

1. 通常比较 `baseline + 1–3 个真正相关候选`，不以候选数量制造“高级感”；
2. 使用相同 representative subset / reduced dataset、相同信息边界、统一评价口径和相近计算预算；
3. 至少比较：结构匹配、验证表现、稳定性、解释性、计算成本、下游接口；
4. 时间序列、分组、空间任务继续遵守正确的数据切分，不得为了快速原型改用会泄漏的随机切分；
5. 不得反复查看最终测试集来决定主模型；
6. 原型结果必须记录“为什么淘汰”，不能只保留胜者分数；
7. 小样胜出只代表“值得进入正式验证”，不等于已经通过模型证据 Gate。

### 收敛规则

锦标赛结束后必须收敛为：

- 1 个合理 baseline；
- 1 个主模型候选；
- 最多 1 个失败备用方案。

正式主模型仍需经过完整数据、统一验证、敏感性/鲁棒性和独立验收后才能 Freeze。

## Hugging Face / 预训练资产候选

只有当前问题确实需要 ML、预训练模型、外部公开数据或论文对应资产时，才进入 `05_HuggingFace研究资产协议.md` 的条件式 HF Research Lane。

任何进入正式候选池的 Hugging Face / pretrained asset 至少记录：

```text
repo_id
revision / commit SHA
license
framework / task
model or dataset card
hardware
local wrapper / implementation version
local benchmark
```

其中 `hardware` 必须回答当前比赛环境是否能在时间和显存预算内复现；`local benchmark` 必须使用本题冻结数据与评价口径。Hub 热度、下载量、Model Card 指标或第三方排行榜只用于发现候选，不构成主模型选择证据。

## 停止规则

如果新模型：
- 没有解决旧模型的具体缺陷；
- 只提升很小；
- 增加大量不稳定性；
- 论文无法清楚解释；

则不切换主模型。
