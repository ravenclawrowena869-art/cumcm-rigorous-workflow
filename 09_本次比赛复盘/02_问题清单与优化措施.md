# 本次比赛问题清单与 v2.0 对应改造

| 本次出现的问题 | 根因 | v2.0 机制 |
|---|---|---|
| Leader 承担过多技术总控 | Leader 与 Model Integrator 合并 | Paper / Technical / Mathematical 三角色拆分 |
| 一人必须等另一人结果 | 结果依赖被误当成开发依赖 | Interface First + Mock Data |
| FYQ/XXT 曾因工具或任务状态调整角色 | 容灾发生在人员层 | 工具→设备→人员三级容灾 |
| 论文启动太晚 | 把论文当成后期阶段 | 第一次路线评审后立即启动 Paper Pipeline |
| 图表返工多 | 图表被当成最后美化 | Figure Registry + Visualization Pipeline |
| 版本迭代过密 | 小修补也升级核心版本 | 状态机 + Freeze + P0 reopen |
| Q4 集成阻塞 | 接口较晚固定 | 8–10h 前尽量锁 interface schema |
| 指标口径风险 | Paper metrics 未统一 | Paper Handoff + number registry |
| 论文超页后才集中压缩 | 无页数预算 | 前期章节预算 + 持续页数预审 |
| AI 修改容易扩大范围 | Prompt 缺 non-goal | 平台无关 Skill + allow/forbid + validation |
| 团队出现纯等待 | 无备用任务机制 | Blocked Rule + Secondary Queue |
| 模型完成后仍大量工程修补 | 把“跑出来”视为完成 | Technical / Mathematical / Paper 三重验收 |
