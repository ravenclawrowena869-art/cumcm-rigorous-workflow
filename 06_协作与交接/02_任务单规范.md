# 任务单规范

任何超过 30 分钟的任务最好用任务单。任何由 FYQ 主控发出的新 Wave，默认采用 Parallel-First 三任务书制：FYQ、XXT、CYQ 各一份，同一个 Frozen Snapshot，同步启动。

## 好任务单

```text
任务：
负责人：
Authority：
Frozen Snapshot：
输入：
目标：
Primary Work：
允许修改：
禁止修改：
需要输出：
验收标准：
PARALLEL_START：
DEPENDENCY_DECOUPLING：
INTERFACE / MOCK：
INTEGRATION_STEP：
SECONDARY_QUEUE：
截止时间：
依赖：
失败时回退：
Handoff Consumer：
```

## Parallel-First 要求

### PARALLEL_START

必须明确说明本任务在本 Wave 发出后即可启动。不得把“等另一成员先完成并交包”写成启动条件。

### DEPENDENCY_DECOUPLING

如果最终需要另一成员的新结果，必须先说明如何用以下一种或多种方式解耦：

- Frozen Interface；
- schema；
- Mock；
- Placeholder；
- 上一版本 Frozen Source；
- 独立可验证的局部输入。

### INTERFACE / MOCK

若存在跨角色数据接口，任务书必须提前冻结字段、单位、粒度、版本、缺失/失败行为。Mock 只能用于并行开发，不得冒充正式结果。

### INTEGRATION_STEP

真结果到达后，只允许执行事先声明的短集成动作，例如替换 mock、重跑 parser、复算指标、生成正式图或填入 Frozen Metrics。若集成需要重做主体模型，说明原分包没有真正解耦，应回主控重拆。

### SECONDARY_QUEUE

Primary 被 solver、外部数据、真实硬依赖或接口问题阻塞时，立即切换预先列出的 Secondary Task。团队允许主线 blocked，不允许人纯等待。

## 三份任务书要求

每个正常 Wave 必须同时存在：

- `TASK_<WAVE>_FYQ.md`
- `TASK_<WAVE>_XXT.md`
- `TASK_<WAVE>_CYQ.md`

三份任务书从同一个 Frozen Snapshot 出发。允许 Integration 阶段有依赖，不允许人的启动阶段有依赖。

若某角色本 Wave 确实 `NOT_APPLICABLE`，必须在 Wave manifest 中写清原因及其 Secondary Queue；不能因为“暂时用不上”直接不给任务书。

## 坏任务单

- “继续优化 Q4”
- “帮我看看代码”
- “把图搞好看点”
- “再跑一轮”
- “等 XXT 的包出来以后你再开始”
- “CYQ 先等最终结果再写”

## 图表任务也要有验收标准

例如：
- 必须读取 v4.8 FINAL_FROZEN；
- 横纵轴中文；
- 不允许手工填数字；
- 论文宽度 0.8\textwidth 时可读；
- 输出 PNG + PDF + source script。
