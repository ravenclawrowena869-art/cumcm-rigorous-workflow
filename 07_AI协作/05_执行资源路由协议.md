# 执行资源路由协议 v1.0

本协议用于数学建模比赛中的正式 Task / Prompt 分发。它决定“这个任务应该交给哪一档执行资源”，不改变 FYQ / XXT / CYQ 的长期角色、Authority、Source of Truth、Mathematical Gate、Evidence Gate 或 Freeze 条件。

## 1. 固定词汇

执行器只使用三种标识：

- `CODEX_ASTRA`
- `CODEX_SOL`
- `GPT_EXECUTION`

执行级别只使用三种标识：

- `REQUIRED`
- `PREFERRED`
- `SUFFICIENT`

正式 Task / Prompt 顶部必须写：

```text
【执行资源路由】
推荐执行器：CODEX_ASTRA / CODEX_SOL / GPT_EXECUTION
执行级别：REQUIRED / PREFERRED / SUFFICIENT
选择原因：……
是否允许降级：YES / NO
降级条件：……
升级触发：……

【任务语言】
中文；代码标识符、路径、命令保持原文。
```

## 2. CODEX_ASTRA

`CODEX_ASTRA` 用于错误可能改变正式数学模型、可行性、核心结果、跨模块执行路径或 Frozen 主线的高风险实现。

典型任务：

- 首次实现或实质修改 LP / MILP / CP-SAT / 复杂调度器 / 交替优化 controller；
- objective、hard constraint、unit、accounting、state recursion 的核心实现；
- 从论文或数学规格首次落地非平凡算法；
- exact/MILP anchor 本身复杂，且必须与 heuristic 同目标、同约束、同口径；
- surrogate/full-model、fixed/adaptive controller 等多执行路径状态机；
- 多个核心模块共同修改；
- Frozen 主线出现 P0 后的正式修复；
- solver 与 independent recomputation 冲突；
- Freeze 前仍需修改核心算法路径。

通常使用 `REQUIRED` 或 `PREFERRED`。

`REQUIRED` 表示该任务的实现风险足以影响正式数学路径，正常情况下不应主动降级。`PREFERRED` 表示 Astra 明显更合适，但在数学规格已经冻结且任务可以安全拆成独立小 Block 时允许 Sol 完成。

## 3. CODEX_SOL

`CODEX_SOL` 用于数学定义、接口和验收已经冻结，主要工作是工程落实、测试、批跑、包装和局部修复的任务。

典型任务：

- data loader / schema / CSV 转换；
- experiment runner / seed runner / sweep harness；
- validator / tests / provenance / hash 工具；
- package-relative path 修复；
- CLI wrapper / batch scenario runner；
- 冻结公式下的小范围 bugfix；
- 图表脚本、日志字段、导出格式；
- Astra 完成核心实现后的测试补强。

默认使用 `SUFFICIENT`。

如果执行中需要重新解释目标、约束、单位、accounting、path-dependent state 或核心 Claim，Sol 必须停止自行裁决，回到 FYQ / XXT；必要时触发 Astra 升级。

## 4. GPT_EXECUTION

`GPT_EXECUTION` 用于不需要长期修改真实代码仓库，重点是读取、运行、复算、审查、分析、交接和打包的任务。

典型任务：

- ZIP CRC / SHA / manifest 验证；
- 运行已有 tests / scripts；
- independent metric recomputation；
- CSV 统计与结果解释；
- Controller Review / XXT Mathematical Review；
- evidence matrix / Paper Handoff / Figure Registry；
- 文件比对 / package completeness audit；
- 文献和候选初筛；
- 论文结构审查与 CYQ evidence placeholder；
- AI Use Ledger 整理；
- 打包与下一 Wave 任务书生成。

默认使用 `SUFFICIENT`。

如果 GPT execution 任务演化成需要持续修改真实仓库，应重新路由到 `CODEX_SOL` 或 `CODEX_ASTRA`，不能为了省切换而继续在临时执行窗口堆叠正式代码。

## 5. 30 秒快速路由判定

依次回答：

1. 任务是否需要长期修改真实代码仓库？
2. 是否触及 objective / hard constraints / unit / accounting / state recursion？
3. 错误是否可能 materially 改变 feasibility / solution ranking / core claim？
4. 是否跨多个核心模块或需要重构执行路径？
5. 数学规格是否已经由 Authority / XXT 冻结？
6. 任务主体是实现，还是运行/复算/Review？

快速路由：

```text
无需长期改仓库，主要运行/复算/审查
→ GPT_EXECUTION / SUFFICIENT

需要改仓库，数学与接口已冻结，工程落实为主
→ CODEX_SOL / SUFFICIENT

需要改核心算法、状态机、正式数学路径，或错误可改变正式结论
→ CODEX_ASTRA / REQUIRED 或 PREFERRED
```

## 6. 自动升级

以下任一条件触发：

`EXECUTION_ESCALATION = CODEX_ASTRA`

- 连续两轮 minimal fix 仍未解决根因；
- 修改开始跨多个核心模块；
- 出现 objective / hard constraint / unit / accounting 风险；
- solver 与 independent recomputation 矛盾；
- surrogate 可能 materially 改变正式结果；
- 动态 replay 出现无法解释的 violation；
- 任务从“按规格实现”升级成“重新设计算法”；
- Sol 出现 patch-on-patch；
- 测试数量很多，但仍无法证明真实 execution path。

升级只改变执行资源。执行器不改变角色权限，也不得跳过 XXT Mathematical Review、Evidence Gate 或 Freeze 前置条件。

## 7. Astra 不可用时的降级

如果 Task 标记 `ASTRA_REQUIRED`，但 Astra 临时不可用：

1. 先判断是否可以等待；
2. 若不能等待，将任务拆成更小、边界明确的 Frozen Blocks；
3. 每个 Block 在数学规格冻结后交给 `CODEX_SOL`；
4. 强制 TDD；
5. 强制 independent replay / metric recomputation；
6. objective、hard constraints、unit、accounting、state recursion 等关键数学路径单独送 XXT / GPT Review；
7. 最终 G2 / Mathematical PASS / Evidence Gate / G3 Freeze 条件保持不变。

降级只解决工具可用性，**不得降低 Evidence Gate**，也不得把 `REQUIRED` 在记录中偷偷改成 `SUFFICIENT`。Task / Handoff 必须保留原路由与实际降级原因。

## 8. 面向团队的中文任务书

面向 FYQ / XXT / CYQ 的以下载体默认使用简体中文：

- Task；
- Authority 摘要；
- Handoff；
- Controller routing；
- Missing Evidence；
- 执行说明与验收说明。

以下内容保持原始英文，不机械翻译：

- 文件名、路径、branch、commit、SHA；
- class / function / variable / enum / status code；
- command、schema 字段、测试名；
- 需要与代码、Solver、Git 或外部工具精确匹配的标识符。

任务书的目标是让团队成员能快速人工审阅，同时保持工程接口精确。

## 9. 比赛时典型任务矩阵

| 任务 | 默认执行器 | 级别 | 说明 |
|---|---|---|---|
| 复杂 MILP / controller 首次实现 | `CODEX_ASTRA` | `REQUIRED` | 错误可能改变正式数学路径 |
| 非平凡算法首次从数学规格落地 | `CODEX_ASTRA` | `PREFERRED`/`REQUIRED` | 看是否触及核心可行性/结论 |
| exact anchor 的复杂同口径实现 | `CODEX_ASTRA` | `REQUIRED` | 必须保证目标和约束等价 |
| CSV runner / seed runner / sweep harness | `CODEX_SOL` | `SUFFICIENT` | 前提是数学规格已经冻结 |
| validator / tests / path fix / 打包脚本 | `CODEX_SOL` | `SUFFICIENT` | 工程落实为主 |
| ZIP 验证 / 独立复算 / Controller Review | `GPT_EXECUTION` | `SUFFICIENT` | 不需要长期改真实仓库 |
| XXT Mathematical Review | `GPT_EXECUTION` | `SUFFICIENT` | 角色权限来自 XXT，不来自执行器 |
| Paper Handoff / Figure Registry / evidence matrix | `GPT_EXECUTION` | `SUFFICIENT` | 只消费 Frozen Evidence |

## 10. 禁止误用

- 不因为 Astra 更强就把所有任务都升级到 Astra；
- 不因为使用 Astra 就减少测试、独立复算或 Mathematical Review；
- 不让 Astra 取得 FYQ / XXT / CYQ 之外的 Authority；
- 不让 Astra 成为比赛单点故障；
- 不在任务书未说明的情况下自动消耗高性能额度；
- 不把“用 Sol 足够”理解成允许 Sol 自行修改冻结数学口径。
