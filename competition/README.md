# 单场比赛工作区

本目录承载一场比赛的实际协作、建模与交付文件。开赛后按以下顺序启动：

1. 填写 `project_state.yaml`。
2. 将官方题目、规则和附件放入 `problem/` 与 `data/`。
3. 完成第一次路线评审。
4. 为各模块指定 Owner 与 Reviewer。
5. 启动 Paper、Technical、Mathematical 三条流水线。

根目录的 workflow 原则上在比赛期间只读；比赛事实、任务状态和正式结果以本目录及其冻结产物为准。

原始数据默认不被忽略。若附件过大，不适合普通 Git 管理，应在赛前决定使用 Git LFS、受控存储或明确的数据交接方式。
