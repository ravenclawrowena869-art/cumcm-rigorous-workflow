# 项目状态机与角色责任

每个问题或模块统一使用：

```text
IDEA
 ↓
BASELINE
 ↓
MAINLINE
 ↓
VALIDATING
 ↓
FROZEN
 ↓
PAPER_LOCKED
```

可选：
- BLOCKED
- FAILED_VALIDATION
- REOPENED_BY_P0

## STATE-SEPARATION-001：执行状态与科学状态分离

对于多 Agent、长时间求解或自动化流水线，必须区分“流程还能不能继续跑”和“当前结论是否已经通过科学验收”。

建议至少维护：

```text
execution_status:
  RUNNING / BLOCKED / RETRYING / CONTINUING / STOPPED

validation_status:
  NOT_STARTED / VALIDATING / PASS / PASS_WITH_LIMITATION / FAIL_REOPEN / MATHEMATICAL_P0
```

硬规则：

- `execution_status=CONTINUING` 只表示其他无依赖任务仍可进行，绝不代表当前模块 `validation_status=PASS`；
- Agent 超时、预算不足、重试次数耗尽、工具故障都不能自动把科学 FAIL 改成 PASS；
- `FAIL_REOPEN` / `MATHEMATICAL_P0` 不得进入 `FROZEN`；
- 依赖失败模块的下游任务只能用显式标记的 mock / candidate / placeholder，不能把未验证数字伪装为正式结果；
- 最终 Freeze、Paper Handoff 和 Submission Gate 仍以正式 validation 状态为准。

这样允许“任务继续”，但禁止“科学 Gate 降级转正”。

## STATE-CHECKPOINT-001：checkpoint 与恢复

长任务可在阶段边界保存 checkpoint，但 checkpoint 是**恢复辅助信息**，不是验收凭证。

checkpoint 建议包含：

```text
stage
question/module
source_commit
input_manifest_hash
config/version
completed_artifacts
pending_artifacts
validation_status
blocking_issues
next_action
```

恢复前必须核对：

1. `source_commit` 是否改变；
2. 输入 manifest / hash 是否改变；
3. materially 影响结果的配置、参数、接口是否改变；
4. 旧 Mathematical Review 是否仍对应当前 Source of Truth。

若上述任一项发生实质变化，旧 checkpoint 可以帮助定位进度，但不得据此跳过受影响的代码、数学或证据 Gate。

自动化引擎的 `run_state.json`、日志、PID、临时缓存不属于正式共享状态；正式同步仍以 `project_state.yaml`、Task、Handoff、Frozen Source of Truth、Figure Registry、Git commit / PR 为准。

## 状态负责人

### MAINLINE
Owner 对模块进度负责。

### VALIDATING
- FYQ：Technical Check
- XXT：Mathematical Check

### FROZEN
FYQ 维护技术 Source of Truth；
XXT确认数学口径不再变化。

### PAPER_LOCKED
CYQ完成 Paper Check 后进入。

# 三重验收

## Technical PASS — FYQ
- 输入
- 代码
- tests
- interface
- version
- clean replay
- manifest
- paper metrics source

## Mathematical PASS — XXT
- 数学定义
- 目标
- 约束
- 假设
- 指标
- 边界
- 数值合理性
- 求解逻辑

## Paper PASS — CYQ
- 能否讲清楚
- 结果是否支持结论
- 图表是否有效
- 与全文是否一致
- 是否过度复杂
- 是否存在明显 AI 味

三者通过后才能 `PAPER_LOCKED`。

# 冻结后允许修改

允许：
- 不影响模型结果的路径兼容
- README
- 注释
- 图表样式
- 论文表述
- 打包问题

禁止：
- 目标函数
- 关键约束
- 正式指标口径
- 核心参数
- 手工修改 frozen output

如发现 P0：
1. 宣布 `REOPENED_BY_P0`
2. 新版本
3. 重跑依赖
4. 更新 paper metrics
5. 重画相关图
6. 重新 Paper Check

任何正式数值换版还必须执行 `04_验收冻结/04_结果来源链.md` 中的影响传播与旧值残留检查，避免新旧版本混用。
