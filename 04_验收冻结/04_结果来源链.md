# 结果来源链

所有正式结论都遵循：

```text
官方附件
  ↓
冻结代码
  ↓
冻结输出 CSV/JSON
  ↓
paper metrics
  ↓
图 / 表
  ↓
正文句子 / 摘要
```

## SOURCE-CHAIN-001：正式数字必须可追溯

任何准备进入图表、正文、摘要或下游问题的正式数字，必须能追溯到：

- 当前冻结版本；
- 权威输出文件；
- 明确字段/行列；
- 单位与统计口径；
- 复算/验收状态。

聊天、截图和人工记忆不能覆盖冻结来源。

## CHANGESET-001：正式结果换版必须生成影响清单

如果一个已经被下游问题、图表、表格、正文或摘要消费的正式指标发生变化，不得只在某一个位置手工替换。必须建立“换版影响清单”。

最低字段：

```text
claim_id / metric_name
old_value
new_value
unit
old_freeze_version
new_freeze_version
authoritative_source
reason_for_change
affected_questions
affected_tables
affected_figures
affected_sections
affected_abstract_claims
status
checked_by
```

推荐更新顺序：

```text
重新求解 / 复算
→ 新 Frozen Output
→ 新 paper metrics
→ 下游问题重跑（若依赖）
→ 图表 / 表格更新
→ 正文更新
→ 摘要更新
→ 全文旧值残留检查
→ Paper Check
```

若某个消费方无需修改，也要在清单中明确写 `NOT_AFFECTED + reason`，不能靠默认猜测。

## CHANGESET-STALE-001：旧值残留检查

换版后至少检查：

- 摘要中的旧数字；
- 正文中的旧数字；
- 表格单元格；
- 图中标注、图题、图例；
- 绘图脚本中的硬编码旧值；
- 下游问题缓存/中间文件；
- Paper Handoff / Figure Registry；
- README 或交付说明中的正式结果。

若旧值本身也是合法数字，不能只做裸字符串替换。应结合 `claim_id / metric_name / unit / section` 判断，避免误改无关数字。

发现“新表 + 旧图”“新正文 + 旧摘要”“新结果 + 旧下游缓存”等混版时，Paper Check 必须 FAIL，直到统一到同一冻结版本。

## FROZEN-INPUT-001：随机、合成和仿真输入同样属于来源链

如果核心结果依赖 Monte Carlo、仿真、随机场景、采样集或模型自行生成的合成输入，必须冻结复算所需输入，至少记录：

```text
file
purpose
generation_method
seed/config
sha256
```

独立复算首先使用同一冻结输入验证“同输入同口径能否复现”；随后再通过换 seed、换场景或扰动机制做鲁棒性检查。

## 禁止

```text
聊天里的数字 → 论文
截图里的数字 → 论文
旧图标签 → 新表格
人工重新算但不记录来源 → 论文
旧 Frozen Output + 新 Paper Metrics 混用
结果换版后只改摘要或只改正文
```

## 最终建议建立 `paper_number_registry.csv`

字段：
- section
- claim_id
- metric_name
- value
- unit
- source_file
- source_row
- source_column
- freeze_version
- checked_by

建议额外增加：
- input_hash
- validation_status
- last_changed_commit
- affected_artifacts

这样改论文时不再靠记忆，并能在结果换版时形成可机械检查的影响传播链。
